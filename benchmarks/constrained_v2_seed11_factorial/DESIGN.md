# Design

## Scientific question

The intended study would isolate, under one controlled current runtime, the effects
of the reconstructed training-track stream and reconstructed collection/update
schedule on the seed-11 gap between historical Constrained V2 (Validation RSR 9/9)
and the matched current Real-Only result (Validation RSR 0/9).

It is a mechanistic single-seed study, not an algorithm benchmark and not an exact
historical reproduction.

## Frozen matrix

| Condition | Name | Track stream | Collector |
|---|---|---|---|
| A | `A_histTrack_histCollector_seed11` | `T_HIST` | `C_HIST` |
| B | `B_histTrack_currentCollector_seed11` | `T_HIST` | `C_CURRENT` |
| C | `C_currentTrack_histCollector_seed11` | `T_CURRENT` | `C_HIST` |
| D | `D_currentTrack_currentCollector_seed11` | `T_CURRENT` | `C_CURRENT` |

Every policy would use the same current network constructor, nominal seed 11,
300,000 real transitions, 30,000 updates, and frozen Constrained V2 configuration.

## Track interventions

`T_HIST` is generated by the audit reconstruction: seed the base environment with 11
on the initial reset, continue its `np_random` generator with `seed=None`, and take
used reset draws 0, 2, 4, ... because historical `FastCollector` performs an in-loop
terminal reset and a final reset before returning.

`T_CURRENT` is generated by
`default_rng(SeedSequence([11, 0x4D564531]))`, drawing an explicit signed-31-bit
integer per reset and rejecting reserved numeric split IDs. The generated prefix
matches all 223 reset seeds retained in the archived current seed-11 checkpoint.

The study-level canonical fingerprint covers the task limits, positions, speed
limits, energy factor, and initial observation. Its content comparison—not merely
numeric seed comparison—finds the Development-2006 collision that stops execution.

## Collector interventions

`C_HIST` is the recovered FSRL episode-wise schedule: collect a complete episode with
fixed actor weights, retain the terminal transition in replay, pass the exact
undiscounted two-cost episode vector to PID, and only then perform the accumulated
replay updates. Replay sampling begins after the PID event. The intended equal-budget
implementation would use a deterministic cumulative update budget so the endpoint is
exactly 30,000 updates without updating within an episode.

`C_CURRENT` is the archived current transition-wise schedule: collect one transition,
apply PID only if that transition completed a real episode, catch up to
`floor(real_transitions * 0.1)` updates when replay has at least 256 rows, then collect
the next transition with the potentially updated actor. The terminal transition is in
replay before PID and the terminal-step update catch-up.

## Intended causal contrasts

Had all gates passed, the fixed 300k contrasts for RSR, completion, deadline, and
speed-compliance counts would have been `C-A`, `D-B`, `B-A`, `D-C`, and interaction
`D-C-B+A`. No such contrasts exist because zero conditions started.
