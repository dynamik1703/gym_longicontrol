# RNG and trajectory audit

## Earliest divergence

The earliest deterministic divergence is the **first generated training track**,
before the first action or simulator transition.

The bounded side-by-side ladder uses unreserved audit seed 0 under one installed
runtime. Network construction matches at level 1. The first track differs at level 2,
so levels 4–12 (action through first PID update) are deliberately not executed. This
uses zero LongiControl transitions and follows the instruction to stop once an earlier
divergence explains all downstream state divergence.

For the actual nominal training seeds, the first differing episode index is also 0:

| Seed | Same-index matches among first 100 | First difference | Shared fingerprints anywhere in the two sets | Current generated seeds match checkpoint |
|---:|---:|---:|---:|---|
| 11 | 0/100 | 0 | 1 | Yes |
| 29 | 0/100 | 0 | 0 | Yes |
| 47 | 0/100 | 0 | 2 | Yes |

The few set-level collisions are ordinary repeated profiles; none occurs at the same
episode index. Exact per-episode hashes, speed-limit profiles, energy factors, initial
observations, and current explicit reset seeds are in `results.json` under
`rng_and_tracks.by_seed`.

Episode lengths recovered from historical diagnostics and the current 100k/150k
replay checkpoints also diverge early:

| Seed | First differing episode length index | Same-index length matches among first 100 |
|---:|---:|---:|
| 11 | 1 | 30/100 |
| 29 | 2 | 27/100 |
| 47 | 18 | 25/100 |

An equal length (often the 1,800-step cap early in training) does not imply an equal
track or trajectory. The complete first-100 length vectors are retained in
`results.json`.

## Why the streams differ

Historical training creates the dense wrapper with `initial_seed=training_seed`. Its
first reset seeds the Gymnasium environment; later resets pass `seed=None` and continue
the base environment's `np_random` generator. Environment steps do not consume that
generator; stochastic track generation does so at reset.

Current training creates a dedicated generator from
`SeedSequence([training_seed, 0x4D564531])`, draws an explicit integer for every reset,
rejects reserved split IDs, and re-seeds the base environment with that integer. The
first explicit seeds are therefore unrelated to 11, 29, or 47. The generated first
100 integer sequences exactly match those persisted in all three final checkpoints.

Collector reset consumption introduces a second divergence. A one-step synthetic
fixture measures:

| Path | Resets after construction | Resets after one terminal transition |
|---|---:|---:|
| Historical FSRL `FastCollector`, `n_episode=1` | 1 | 3 |
| Current Tianshou `Collector`, `n_step=1` | 1 | 2 |

The historical collector resets a finished environment inside its loop and then
calls `reset_env()` again before returning from episode collection. Thus one generated
track is discarded between used historical tracks. The reconstructed used sequence
is reset draws 0, 2, 4, … . The current collector retains the one post-terminal reset
for the next step call.

Historical actual track definitions were not persisted. Their first 100 hashes are
therefore a source-exact reconstruction under NumPy 2.4.6/Gymnasium 1.4.0, not proof
of the bytes generated by the unrecorded historical NumPy/Gymnasium runtime. Equality
is nevertheless not theoretically guaranteed: the two source paths intentionally use
different generator construction and reset consumption.

## RNG ownership and consumption

| RNG | Historical | Current | Finding |
|---|---|---|---|
| Python `random` | FSRL `seed_all(seed)` | same | Same initial call; later Python-random use not found on core path |
| NumPy global | FSRL `seed_all(seed)`; replay uses `np.random.choice` | same initial call; replay same | Conditional parity only if prior state and replay match |
| Dedicated NumPy generator | none for track IDs | track stream plus separate MVE rollout stream | Track stream changes training trajectory; rollout stream is unused for M=0 target generation |
| Torch CPU | `torch.manual_seed(seed)`; actor sampling | same | Same seed call; consumption diverges once collection/update cadence differs |
| Torch accelerator | CUDA seed calls, but CPU device | same | Inactive for both runs |
| Environment/track | one continuous base generator | newly seeded base generator per reset | Different at episode 0 |
| Collector | no private RNG found | no private RNG found | Difference is call/reset cadence |
| Checkpoint/recovery | not retained; no resume evidence | captures/restores states; all Real-Only attempts completed without resume | No evidence recovery consumed training RNG |
| Diagnostics/sidecar | absent | dedicated diagnostic/rollout generators | Designed separately; no M=0 policy-update draw, but surrounding runner still differs |
| Evaluation | explicit fixed environment seeds, deterministic actor | same | Equivalent and isolated from completed training |

It is therefore impossible to report proven historical initial hashes. Reconstructing

## Replay RNG fixture

Tianshou 0.5.1 `ReplayBuffer.sample_indices` uses the legacy global NumPy RNG. With
an identical fixture buffer and NumPy state, repeated samples are identical:
`[4, 6, 2, 4, 1, 5]`. The deterministic two-step fixture also fixes successor indices,
reward/cost order, done masks, and target inputs; its output SHA-256 is
`1d9cc296f3459f21090f1cbce849933d045bc8de3b8416bc20f8fb1c6053768d`.

This is conditional replay parity. The real runs do not satisfy the prerequisites:
their first track, episode cadence, replay contents, global NumPy consumption, and
policy state already differ.
